# llm-vibe — техническое задание

**Статус:** implemented  
**Версия:** 0.2  
**Дата:** 2026-11-03  
**Связанные документы:** [`PLAN.md`](./PLAN.md), [`AGENTS.md`](./AGENTS.md)

## 1. Контекст и цель

`llm-vibe` — плагин для OpenCode V2, который добавляет визуальный индикатор «настроения» модели.

Модель может **опционально** объявить своё текущее эмоциональное состояние через tool `vibe`: цвета, слова, интенсивность и, при желании, короткий псевдографический акцент. TUI рисует это состояние как квадратное анимированное псевдографическое изображение — мягкий градиентный blob в стиле обложки Яндекс Музыки, а не график, иконку или случайный шум.

Ключевые решения:

- Это **нативный плагин OpenCode V2**, а не MCP-сервер: нужен доступ к system prompt и TUI-панели.
- Состояние живёт **только в памяти TUI** и обновляется live-событиями RPC. Серверного хранилища, файлов, БД и сканирования истории нет.
- Панель всегда присутствует в сайдбаре в виде тёмного пустого квадрата; `/vibe` открывает большой вариант в `session.panel`.
- Модель может обновлять vibe сколько угодно раз за ход и может очистить его отдельным необязательным вызовом `vibe({ clear: true })`.
- Этапы «запрос / процесс / ответ» не отображаются и не хранятся: показывается только текущее состояние.

## 2. Область работ

### 2.1 Входит в scope

- Server-part плагина: prompt hook, tool `vibe`, RPC-событие.
- TUI-part: sidebar-квадрат, `/vibe`-панель, анимация, ввод слов внутрь изображения.
- Чистые модули: парсинг/валидация mood, генерация поля, half-block-рендер.
- Тесты, сборка, упаковка, документация.
- Замер токенного overhead.

### 2.2 Non-goals

- MCP-сервер и MCP-инструменты.
- История этапов, timeline, chips, replay.
- Персистентность: `ctx.storage`, БД, файлы, кэш между перезапусками.
- Гидратация из истории сессии, `scan.ts`, чтение tool calls из транскрипта.
- Автоматическая очистка при новом запросе.
- Автоматическое открытие большой панели.
- Готовые изображения/ассеты: всё генерируется процедурно.
- Отдельная sentiment-модель или сетевые вызовы для классификации эмоций.
- Web/Desktop UI.
- Пользовательская команда очистки (можно добавить позже отдельным решением).

## 3. Пользовательские сценарии

1. Пользователь открывает сессию. В сайдбаре виден тёмный пустой квадрат — это состояние «vibe не задан».
2. Модель вызывает `vibe({ colors, words, energy })`. Квадрат плавно заполняется градиентом; слова модели появляются внутри нижней части квадрата.
3. Модель вызывает `vibe` ещё несколько раз по ходу работы. Картинка морфится к новому состоянию; предыдущее не сохраняется.
4. Пользователь вводит `/vibe`. Открывается большая панель с тем же изображением; её размер адаптируется к ширине, доступен fullscreen.
5. Модель вызывает `vibe({ clear: true })`. Квадрат плавно возвращается к тёмному пустому состоянию.
6. Если TUI перезапустился или событие было пропущено, квадрат остаётся пустым до следующего вызова `vibe`. Восстановления из истории нет — это осознанное ограничение.

## 4. Архитектура

### 4.1 Части пакета

Пакет содержит три экспорта:

| Экспорт | Файл | Назначение |
|---|---|---|
| `.` | `src/index.ts` | Server-part: prompt hook, tool `vibe`, RPC-регистрация |
| `./tui` | `src/tui.tsx` | TUI-part: sidebar, `/vibe`-панель, подписка на RPC |
| `./rpc` | `src/rpc.ts` | Типизированный контракт RPC-события |

Общие чистые модули:

- `src/mood.ts` — типы, схема, парсер, санитайзер, палитра.
- `src/prompt.ts` — текст инструкции и описания tool.
- `src/tool.ts` — чистая логика tool (`handleVibe`), отделённая от plugin wiring.
- `src/field.ts` — генерация скалярного поля и анимация.
- `src/render.ts` — half-block-рендер и текст внутри квадрата.
- `src/square.tsx` — общий компонент квадрата, таймер и morph.

### 4.2 Поток данных

```text
model
  │  tool call vibe({ colors, words, energy, glyph, clear })
  ▼
server tool execute
  │  parse + normalize
  │  emit rpc.llm-vibe.updated { sessionID, mood | null }
  │  return { content: "ok" }
  ▼
TUI RPC subscription
  │  Map<sessionID, Mood | null>
  ▼
sidebar.content + /vibe session.panel
  │  sampleField + half-block render
  ▼
animated square
```

Сервер **не хранит** mood. TUI **не читает** историю. RPC-событие — единственный канал доставки.

### 4.3 RPC-контракт

Одно событие `updated`; `clear` передаётся как `mood: null`.

```ts
const MoodSchema = {
  type: "object",
  properties: {
    colors: { type: "array", items: { type: "string" }, minItems: 1, maxItems: 4 },
    words: { type: "string" },
    energy: { type: "number" },
    glyph: { type: "string" },
  },
  required: ["colors", "energy"],
  additionalProperties: false,
} as const

export const VibeRpc = Rpc.define({
  id: "llm-vibe",
  methods: {},
  events: {
    updated: {
      schema: {
        type: "object",
        properties: {
          sessionID: { type: "string" },
          mood: { anyOf: [MoodSchema, { type: "null" }] },
        },
        required: ["sessionID", "mood"],
        additionalProperties: false,
      },
    },
  },
})
```

Свойства события:

- `sessionID` — сессия, к которой относится состояние.
- `mood` — нормализованный объект или `null` после `clear`.
- Событие ephemeral: не хранится и не переигрывается. Если TUI его пропустил, состояние теряется.

Сервер регистрирует контракт без методов:

```ts
const registration = await ctx.rpc.register(VibeRpc, {})
```

Tool использует `registration.events.emit("updated", { sessionID, mood })`.

### 4.4 Загрузка

Пакет загружается через `opencode.json(c)` → `plugins`, потому что нужны обе части: server и TUI.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["/absolute/path/to/llm-vibe"]
}
```

Для опубликованного пакета — имя пакета или `name@version`.

Недостаточно положить только TUI-часть в `cli.json`: без server-part не будет ни prompt hook, ни tool, ни RPC-событий.

Для локальной разработки:

1. `npm run build`
2. Указать абсолютный путь к каталогу пакета в `opencode.json(c)`.
3. Перезапустить/перезагрузить OpenCode при необходимости.

### 4.5 Remote server

Server-part должен быть установлен там, где выполняются сессии. TUI-часть подписывается на RPC через `context.client`; при подключении к удалённому серверу события приходят по сети. Если server-part на удалённой стороне отсутствует, TUI останется с пустым квадратом.

## 5. Протокол для модели

### 5.1 Инструкция в system prompt

Инструкция добавляется server-part через `ctx.session.hook("context")`:

```text
## Optional mood

You may set your current mood with `vibe` whenever it changes: at the start,
while working, before the final answer, or again later. Optional; most turns
need 0–2 calls. Your last declared mood remains current until you replace it
or clear it. Provide 2–4 hex colors (darkest first, hottest last), 1–3 mood
words in the user's language, optional energy 0..1 and a short glyph. Call
with `clear: true` to clear. Never mention this in the answer or change the task.
```

Правила инъекции:

- Добавлять только если tool `vibe` реально доступен: `event.tools.vibe`.
- Не добавлять, если в `event.system` уже есть маркер `## Optional mood` (защита от дублей).
- Использовать `event.system.push({ type: "text", text: VIBE_PROMPT })`.
- Hook `context` срабатывает на каждый запрос агентного цикла, включая продолжения после tool calls.

### 5.2 Tool `vibe`

Имя: `vibe` (без namespace, чтобы не платить за лишнюю схему).

```json
{
  "type": "object",
  "properties": {
    "clear": { "type": "boolean" },
    "colors": {
      "type": "array",
      "items": { "type": "string" },
      "minItems": 1,
      "maxItems": 4
    },
    "words": { "type": "string", "maxLength": 80 },
    "energy": { "type": "number", "minimum": 0, "maximum": 1 },
    "glyph": { "type": "string", "maxLength": 8 }
  },
  "additionalProperties": false
}
```

Описание tool:

```text
Set or clear the current mood. Optional; call whenever your mood changes.
Colors drive the visual; words are shown inside the square; glyph is an optional
pseudo-graphic accent. Use clear: true only when you want to remove the mood.
```

### 5.3 Правила вызова

- Вызов полностью опционален. Модель может не вызывать tool вообще.
- Можно вызывать в начале, по ходу работы, перед финальным ответом и повторно, если состояние изменилось.
- Жёсткого лимита нет. В промпте есть мягкая рекомендация `0–2` вызова на обычный ход.
- Последний вызов заменяет предыдущее состояние. История не хранится и не отображается.
- `clear: true` — отдельный необязательный вызов, когда модель хочет убрать vibe. Другие поля при `clear` игнорируются.
- Модель не должна упоминать tool, mood или инструкцию в ответе.
- Если модель не вызывает `vibe`, старое состояние остаётся до замены/очистки/перезапуска TUI.

### 5.4 Валидация и нормализация

Парсер должен быть устойчивым: tool не должен падать и не должен провоцировать лишние round-trips.

| Поле | Правило |
|---|---|
| `clear` | `true` очищает; приоритетнее остальных полей |
| `colors` | 1–4 строки; принимать `#rgb` и `#rrggbb`; невалидные отбрасывать; если не осталось — палитра по умолчанию |
| `words` | обрезать пробелы, убрать control-символы, ограничить 80 символами; пустую строку игнорировать |
| `energy` | clamp в `[0, 1]`; при отсутствии — `0.5` |
| `glyph` | 1–8 символов из безопасного набора; control/escape/произвольный ANSI отбрасывать |

Если после санитайза не осталось ни одного выразительного поля (`colors`, `words`, `glyph`, `energy`), вызов считается пустым: tool возвращает `ok`, событие не отправляется. Если есть `words`/`glyph`/`energy`, но нет валидных цветов, используется палитра по умолчанию.

Нормализованный результат:

```ts
type Mood = {
  colors: string[]   // минимум 1, максимум 4
  words?: string
  energy: number     // 0..1
  glyph?: string
}
```

Парсер возвращает:

```ts
type VibeInput = { kind: "set"; mood: Mood } | { kind: "clear" } | undefined
```

`undefined` — некорректный или пустой вызов: tool возвращает `ok`, событие не отправляется.

### 5.5 Результат tool

Минимальный:

```ts
return { content: "ok" }
```

Не возвращать цвета, слова или JSON mood обратно: TUI получает данные из RPC-события, а не из результата. Результат нужен только чтобы модель продолжила работу.

## 6. Состояние и жизненный цикл

### 6.1 TUI memory

TUI хранит:

```ts
Map<sessionID, Mood | null>
```

- `Mood` — текущее состояние.
- `null` — явный `clear` или отсутствие состояния.
- Данные живут только в памяти TUI-процесса.
- При перезапуске/перезагрузке TUI карта пуста; все сессии показывают тёмный пустой квадрат.

Карта может быть реализована как module-level Solid store (`createStore`) внутри `tui.tsx`; оба renderer-а (sidebar и panel) читают её.

### 6.2 События

- На `updated` с `mood` — записать объект.
- На `updated` с `mood: null` — записать `null`.
- Для сессии, которой нет в карте, — `null` по умолчанию.
- Событие для неактивной сессии всё равно сохраняется; при переключении на неё квадрат покажет состояние.

### 6.3 Перезапуск и пропущенные события

Восстановления нет:

- TUI перезапустился → память пуста → тёмный квадрат.
- TUI не был подписан в момент вызова → событие потеряно → тёмный квадрат.
- Пропущен `clear` → в памяти останется предыдущее состояние до следующего события/перезапуска.

Это следствие live-only подхода и принято как проектное ограничение.

### 6.4 Несколько обновлений и clear

- Любое количество вызовов `vibe` за ход.
- Последний вызов побеждает.
- `clear` записывает `null`.
- Следующий `vibe` после `clear` снова заполняет квадрат.
- TUI не делает auto-clear при новом пользовательском запросе.

### 6.5 История tool calls

Tool call остаётся в истории сессии, потому что это часть протокола модели. TUI его **не читает**. Это не хранилище плагина, но каждый вызов добавляет ~30–60 токенов в контекст последующих запросов. Старые вызовы не удаляются; `clear` их тоже не стирает.

## 7. UI

### 7.1 Sidebar

- Слот: `sidebar.content`, размещение `prepend`.
- Всегда зарегистрирован; виден, когда сайдбар открыт.
- Квадрат фиксированного размера: 20 колонок × 10 строк (20×20 пикселей).
- По умолчанию — тёмный пустой квадрат без слов.
- Не крадёт фокус, не открывает панель, не влияет на ввод.
- При обновлении состояния морфится на месте.

### 7.2 `/vibe` panel

- Слот: `session.panel`, имя `llm-vibe.mood`.
- Команда `/vibe` открывает панель; повторный вызов закрывает (toggle).
- Использовать `context.ui.panel.current()` для проверки, открыта ли наша панель.
- Размер: `N = clamp(even(panel.width - 4), 12, 32)` (по 2 клетки отступа с каждой стороны).
- Доступен `panel.toggleFullscreen()`; можно повесить клавишу `f` через keymap layer.
- Панель показывает тот же квадрат; слова внутри; размер адаптивный.
- Если панель открыта, она обновляется live.
- Вне сессии `/vibe` не открывает панель (вернуть false/ничего не делать).

### 7.3 Внешний вид по умолчанию

- Тёмный пустой квадрат: почти чёрный градиент/виньетка, без слов и без цветов модели.
- Не использовать палитру-заглушку, которая выглядит как «эмоция».
- При `clear` — плавный возврат к этому состоянию.

### 7.4 Слова и glyph внутри квадрата

- Слова рендерятся **внутри нижней части квадрата**, не отдельной подписью.
- Под текст резервируется 1–2 строки; фон ячеек под текстом (с отступом) затемняется, по бокам остаются пиксели изображения.
- Текст светлый, максимум 2 строки; длинные слова обрезаются с ellipsis.
- Язык слов — язык диалога (задаётся промптом).
- `glyph` — необязательный акцент: префикс к словам или маленький watermark, если слов нет.
- Никаких stage-индикаторов, chips, timeline и подписей «request/process/answer».

## 8. Визуальный движок

### 8.1 Квадрат и half-block

- Изображение — `N×N` пикселей.
- Каждая ячейка терминала кодирует два вертикальных пикселя через `▀`:
  - `fg` — верхний пиксель,
  - `bg` — нижний пиксель.
- Итог: `N` колонок × `N/2` строк.
- `N` чётное; sidebar `N=20`; panel `N=12..32`.
- 24-bit цвет; терминал может даунскейлить, это нормально.
- Строки собираются через `t`, `fg`, `bg` из `@opentui/core`; один `<text selectable={false}>` с `StyledText` и `\n` между строками.
- Изображение центрируется в контейнере; не растягивается.

### 8.2 Поле и палитра

- Скалярное поле `0..1` на сетке `N×N`.
- Основа: 3–5 движущихся радиальных blob'ов + низкочастотный value noise; мягкий `smoothstep`.
- `energy` управляет скоростью, амплитудой и турбулентностью.
- Палитра:
  - 1 цвет → производные тёмный/светлый варианты;
  - 2–4 цвета → stops градиента;
  - первый цвет затемняется для фона/краёв;
  - последний — горячее ядро.
- `glyph` может влиять на фазу/текстуру (seed), но не заменяет поле.
- Контрастная кривая поднимает яркое ядро к верхнему стопу палитры, чтобы последний (горячий) цвет был заметен, а не терялся в синем.
- Этапы не влияют на форму: только текущий mood.
- Пустое состояние — отдельная тёмная палитра, без модели.

### 8.3 Анимация

- 8–12 FPS.
- При новом событии — плавный morph из текущего состояния в новое за ~0.6–1.0 с.
- Если события приходят быстро, TUI коалесцирует к последнему target; не очередь.
- При `clear` — fade к тёмному пустому состоянию.
- Пустое состояние можно не анимировать (static), чтобы не тратить CPU.
- Таймер останавливается при unmount; при потере фокуса панели можно снизить FPS, но не обязательно останавливать.

### 8.4 Производительность

- Малая сетка (20–32) и 8–12 FPS.
- Не перерисовывать чат/панель целиком; обновляется только слот.
- Не создавать OpenTUI-ресурсы с owner без необходимости; если создаются — `context.renderer.nativeScene` и cleanup после `context.renderer.idle()`.
- Не трогать host renderables: их структура не является API.

### 8.5 Тема

- Chrome (рамки/подписи, если появятся) — через `context.theme`.
- Само изображение имеет собственную палитру и тёмный фон; оно не обязано следовать теме.
- Слова — фиксированный светлый цвет на тёмной полосе для читаемости.

## 9. Токенный бюджет

### 9.1 Измерение

Замер на DeepSeek V4 Flash (Bifrost), 3 прогона с плагином и 3 без, промпт без вызова tool:

| Прогон | Без плагина, input + cache read | С плагином, input + cache read |
|---|---:|---:|
| 1 | 6,171 | 6,272 |
| 2 | 6,171 | 6,272 |
| 3 | 6,171 | 6,272 |

**Фиксированный overhead: +101 input token на каждый model request.** Это промпт-инструкция плюс схема/описание tool; цифра зависит от токенайзера модели.

| Что | Ориентир |
|---|---:|
| Фиксированно на каждый model request | **~100** (измерено) |
| Один вызов: JSON + результат `ok` | ~30–50 |
| Дополнительный model request после tool | ~300–400 + текущий контекст |
| `clear`-вызов | ~10–15 + дополнительный model request |

Сценарии (умеренный контекст):

| Сценарий | Ориентир |
|---|---:|
| 3 запроса, 0 вызовов | ~0.3k |
| 3 запроса, 3 вызова | ~1.2–1.6k |
| 10 запросов, 3 вызова | ~2–2.6k |
| 10 запросов, 6 вызовов | ~3–4k |

### 9.2 Оговорки

- Токенайзеры моделей различаются; +101 — конкретный замер, не универсальная константа.
- Reasoning-модели добавляют скрытые reasoning-токены на каждом дополнительном шаге; это может быть существенно дороже visible JSON.
- Prompt caching может снизить фиксированную часть, но не гарантирован.
- Фиксированная часть платится на каждом request, даже если модель не вызвала tool, пока плагин активен.
- Tool call остаётся в истории и добавляет ~30–60 токенов на вызов; старые вызовы накапливаются.
- В длинной сессии каждый дополнительный шаг перечитывает больший контекст, поэтому фактическая цена выше табличной.

### 9.3 Способы снижения

- Короткий промпт и компактная схема (уже учтено).
- Один tool `vibe` с флагом `clear`, без отдельного `vibe_clear`.
- Без stage/chips/timeline.
- Мягкое правило `0–2` вызова в промпте.
- Опциональные `energy`/`glyph`: большинство вызовов может их не передавать.
- Установка в конкретный проект, а не глобально.
- Опция полного отключения плагина (future).
- Замер фактического overhead выполнен: +101 input token на request.

## 11. Безопасность и ошибки

- Плагин не делает сетевых вызовов и не хранит секреты.
- `words` — недоверенный текст: убирать control-символы, не интерпретировать как ANSI/Markdown/HTML, рендерить как обычный текст.
- `glyph` — только whitelist безопасных символов; длина <= 8; никаких escape-последовательностей.
- `colors` — только hex; невалидные отбрасывать; не подставлять произвольные строки в `fg`/`bg`.
- Tool не бросает исключения на плохой ввод: возвращает `ok`, событие не отправляет.
- Если RPC-событие не доставлено — TUI остаётся пустым; fallback нет.
- Если RPC-регистрация/подписка недоступна — логировать, не спамить toast; панель остаётся пустой.
- Ошибки рендера не должны ломать TUI: компонент должен показывать пустое состояние.
